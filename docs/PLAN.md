# 练迹 · 训练日志 — Flutter 安卓 App 完整开发计划（M3 融合版）

## 一、目标、范围与技术架构

开发一款以力量训练记录为核心，兼顾有氧、训练计划和身体数据的个人健身应用。产品暂定名为 **「练迹 · 训练日志」**。

本计划同时覆盖真实业务与 UI 系统；新增的 Material Design 3 专项要求作为完整应用的设计规范。

### 已确定范围

- 本次只交付 Android，兼容 Android 8.0 及以上；保留 Flutter，暂不开发 iOS。
- 核心功能完全离线可用，训练数据可靠保存，支持异常退出后恢复。
- WebDAV 首版提供单手机备份与换机恢复。
- 多安卓设备双向同步、安卓与网页同步、iOS 和纯鸿蒙列为后续阶段。
- 现有网站继续保留，首版通过 JSON 文件迁移数据。
- 不建立账号或自有服务器，不加入 AI 训练处方、应用商店上架和自动更新，不依赖不必要的付费服务。
- 模拟数据仅用于开发预览和测试，不进入正式训练记录。

### 技术架构

| 模块 | 方案 |
|---|---|
| 框架 | Flutter + Dart |
| UI | Material Design 3，适度吸收 M3 Expressive |
| 状态管理 | Riverpod |
| 页面导航 | go_router |
| 本地数据库 | SQLite + sqflite |
| 图表 | fl_chart |
| 安卓系统能力 | 独立适配通知、闹钟、后台备份、文件选择及安全凭据存储 |
| 代码分层 | 界面、业务逻辑、数据访问分离，按功能模块组织 |

初始化时确认 SDK 与依赖兼容性，固定稳定版本及构建方式。Expressive 采用层级、形状、排版和反馈的设计方法；具体组件以选定 Flutter 版本实际支持的能力为准，不将设计规范中的全部组件视为已经具备的 API。[Flutter Material 组件目录](https://docs.flutter.dev/ui/widgets/material)

## 二、功能与数据规则

底部导航为 **「首页、训练、统计、我的」**。计划、模板和动作库归入「训练」，历史可从首页及训练入口进入。

### 首页与训练计划

首页展示欢迎信息、今日日期、今日训练或休息日、开始或继续训练、本周次数与目标进度、累计训练时长、上次训练摘要、最近动作和历史快捷入口。

- 支持快速记录、自由训练、从模板开始及按每周安排开始训练。
- 动作库包含常见动作、自定义动作、收藏、主要肌群和器械分类。
- 模板保存动作顺序、目标组数、次数或时长、参考重量与休息时间，支持创建、编辑、复制和删除。
- 每周从星期一开始，每天可安排模板或休息日。
- 提供胸、背、肩、手臂、腿及全身的可编辑示例模板，不生成正式训练记录，不表述为个性化处方。
- 开始训练时生成独立快照，之后修改或删除模板不影响训练历史。

### 训练过程与逐组记录

正在训练页面为交互设计的最高优先级，突出当前动作、重量、次数、完成当前组、训练计时和休息倒计时。

每组独立保存数据，支持：

- 新增、修改、删除和完成标记。
- 复制上一组、快捷增减重量。
- 查看上一次相同动作的记录。
- 逐组感受、身体状态及备注。
- 添加动作、调整顺序、跳过动作和提前结束。

复制或新增的组默认为未完成，确认完成才计入实际完成量。有效编辑及时保存草稿，完成操作立即入库；防止连续点击生成重复记录。

训练会话保存开始与结束时间、暂停区间、动作顺序、各组结果、整体感受及恢复备注。支持暂停、继续和异常退出后恢复。首版同一设备最多保留一个进行中的训练会话。

### 训练类型与计算口径

| 类型 | 记录与计算 |
|---|---|
| 器械、杠铃等外部负重 | 记录总外部重量、次数、组数；训练量为重量 × 次数 |
| 哑铃 | 保存单只重量和单双侧方式；按实际左右次数之和计算训练量 |
| 辅助器械 | 单独保存辅助重量，不当作实际负重，不并入外部负重总量 |
| 有氧 | 保存时长及适用的距离、速度、阻力或档位，独立统计 |

例如每只哑铃 5 kg、左右各 8 次，训练量为 `5 × (8 + 8) = 80 kg·次`。

旧记录无法判断重量或左右次数口径时，保留原值并标记未明确，不自动推算。

### 感受、身体状态与计时

- 感受：轻松、适中、吃力、接近力竭。
- 身体状态：无痛、正常肌肉酸胀、轻微不适、明显疼痛。
- 未填写保持为空；明显疼痛仅显示简短温和提示，不作医学诊断，不阻止保存。
- 休息提供 60、90、120 秒及自定义时长，支持开始、暂停、延长和取消。
- 使用截止时间恢复倒计时，通过安卓系统闹钟与通知支持后台和锁屏提醒。
- 按需申请通知和精确提醒权限；拒绝后保留应用内计时并说明限制。取消、重设和延长必须同步撤销或更新旧提醒。

### 历史、统计与身体数据

历史提供日历、时间线、日期查看、动作筛选、整次训练详情、编辑和删除确认；支持将历史训练复制为模板，不复制原完成状态和时间。

统计包括训练次数、训练天数、训练时长、完成组数、有氧时长、外部负重训练量、肌群分布及单动作趋势。

- 时间筛选统一提供最近 7、30、90 天，本周、本月、本年及全部时间。
- 展示指标卡、训练量柱状图、重量趋势折线图和肌群分布图。
- 计划目标与实际完成量分别展示。
- 只计算已完成组；进行中的训练已完成组也计入实际组数和训练量。
- 训练次数按包含有效完成记录的已结束会话计算；训练天数按实际训练日期去重。
- 会话时长扣除显式暂停，正常组间休息计入训练时长。
- 肌群分布按动作主要肌群的完成组数统计，避免重复累计。
- 图表同时提供数值、标签或图例，不只用颜色表达含义。

身体数据支持按日期记录体重及可选腰、胸、臀、上臂、大腿围度，提供趋势；缺失值不按零计算。

## 三、Material Design 3 UI 系统

### 设计依据与参考图

以 Google M3 为基础建立健身产品视觉语言，适度使用 Expressive 的强调层级、形状、排版和动态反馈。[Material Design 官方规范](https://m3.material.io/)

用户随后提供的图片用于确定布局、视觉密度、卡片和品牌细节；与规范冲突时保留可读性、触控效率和无障碍要求。参考图不能减少已经确定的业务功能。

### 三套品牌主题

三套配色共用同一组件和布局体系，在主题变量层调整色彩及有限的形状细节。

| 品牌 | 浅色方向 | 深色方向 |
|---|---|---|
| 冰川蓝 | 冷白、冰蓝、深蓝文字 | 深海蓝、浅蓝强调色 |
| **活力橙，默认** | 暖白、活力橙、深灰文字 | 炭黑、明亮橙色、暖灰 |
| 鼠尾草绿 | 奶油白、鼠尾草绿 | 森林绿、浅薄荷绿 |

品牌与外观模式独立保存：`BrandTheme` 管理三套品牌，`ThemeMode` 管理跟随系统、浅色、深色。

首次启动使用「活力橙 + 跟随系统」。首版不引入壁纸动态取色，避免覆盖用户选择的品牌。

### 颜色、排版与主题接口

建立统一的 `AppTheme`、`ThemeTokens` 和按需使用的 `ThemeExtension`。

- 使用 `ColorScheme` 的 primary、secondary、tertiary、container、surfaceContainer 系列、outline、error 及对应 on 色。
- 页面不得散落硬编码颜色；成功、提醒和图表系列等额外颜色通过语义化扩展统一提供。
- 使用 M3 `TextTheme` 的 Display、Headline、Title、Body、Label 管理字号、字重和行高。
- 统一管理间距、圆角、组件密度及动效时长，不按页面另建视觉规则。
- 数字与单位分层；重量、次数和组数突出显示，计时使用等宽数字，数值输入尽量右对齐。
- 中文优先使用系统可读字体，不依赖联网加载字体。

颜色角色与文字配色遵循 Flutter M3 语义体系，并逐套检查对比度。[ColorScheme 官方说明](https://api.flutter.dev/flutter/material/ColorScheme-class.html)

### 明暗模式与外观设置

- 三套品牌分别实现浅色和深色，共六套基础外观。
- 手动切换即时生效并持久化；重启后恢复。
- 手动明暗选择不被系统覆盖；跟随系统时实时响应系统外观变化。
- 页面、弹窗、底部面板、输入框、图表、SnackBar 和系统栏同步更新。
- 启动时先恢复外观偏好，不先渲染默认浅色页面再切换。
- 外观设置提供主题卡片、选中标记及局部实时预览；浏览预览不意外改变当前配置。
- OLED 纯黑仅预留扩展位置，首版不提供无实际功能的开关。

### 组件与页面交互

| 场景 | 基础组件 |
|---|---|
| 手机主导航 | NavigationBar |
| 宽屏导航 | NavigationRail |
| 页面顶部 | AppBar / SliverAppBar |
| 开始训练、完成当前组 | FilledButton |
| 次要操作 | FilledButton.tonal / OutlinedButton |
| 添加动作 | FAB 或明确的添加按钮 |
| 动作与训练卡片 | Card / ListTile |
| 搜索与筛选 | SearchBar / FilterChip |
| 模式选择 | SegmentedButton / RadioListTile |
| 重量与次数 | TextField，匹配数字键盘 |
| 删除确认 | AlertDialog |
| 动作选择 | Modal Bottom Sheet |
| 操作反馈 | SnackBar |

封装 `AppScaffold`、`WorkoutCard`、`ExerciseCard`、`WorkoutSetRow`、`StatCard`、`ProgressCard`、`ThemeSelector`、`EmptyState`、`LoadingState` 和统一错误状态。

组件覆盖默认、按下、选中、禁用、加载及错误状态。加载中的保存操作防止重复提交；错误说明靠近相关输入，不依赖短暂提示。

页面要求：

- **首页**：开始或继续训练具有最高操作优先级。
- **正在训练**：已有有效数据时，可直接完成当前组；焦点、数字键盘和底部操作区正确协作，避免每组重复打开弹窗。
- **动作选择**：搜索、肌群筛选、器械分类、收藏、最近使用、动作图标与自定义入口。
- **历史**：控制卡片密度，支持日历、时间线和完整详情。
- **统计**：筛选明确，图表与数据空状态完整适配六套外观。
- **我的**：本地昵称与偏好、训练目标、身体数据、导入导出、WebDAV、外观及关于；不显示虚假的登录状态。
- **计划与身体数据**：使用同一设计系统，不因专项示例只列七页而遗漏。

### 动效、响应式与无障碍

- 动效用于完成反馈、状态变化、页面过渡和主题切换，不改变正在输入区域的稳定布局。
- 避免无意义的渐变、阴影和持续动画；响应系统减少动画偏好。[Flutter 动画偏好接口](https://api.flutter.dev/flutter/widgets/MediaQueryData/disableAnimations.html)
- 宽度小于 600 dp 使用底部导航与单列；600 dp 及以上使用侧边导航；840 dp 及以上允许首页、统计和历史采用双列。
- 正在训练页面始终保留明确主操作，不因横竖屏或宽屏变化丢失输入、滚动位置和训练状态。
- 处理 SafeArea、系统栏、手势区、键盘遮挡和安卓返回行为；退出训练页面不等于结束训练。
- 主要触控区域至少 48 dp；提供语义标签、合理朗读顺序和非颜色状态标识。
- 覆盖系统字体放大至 200%，允许换行和重排，不裁切重要数据及按钮。
- 基础适配安卓手机、横屏和安卓平板；本次不包含 iPhone 验收。

## 四、数据可靠性、迁移与 WebDAV

### 本地数据与接口

建立动作、模板、周安排、训练会话、训练动作与组、身体测量和设置模型。业务实体保留稳定 ID、创建与修改时间及删除标记。

界面通过仓储接口访问数据，测试与预览可注入模拟仓储；正式构建使用真实 SQLite。主题偏好通过独立设置接口持久化，并纳入新版完整备份。

数据库使用明确升级迁移，不删除重建。重要修改使用事务，校验输入并处理异常退出、重复提交及无效数据。

### 文件迁移与备份

- 获取现有网站源码及真实 JSON 样例后，核对字段、ID、日期和统计算法，再实现兼容导入。
- 旧网页导入属于追加导入：预览数量与冲突，默认保留本地数据、跳过重复项，校验后事务写入。
- 新版完整 JSON 带格式版本，包含业务数据及可迁移设置。
- CSV 用于分析，不承担完整恢复。
- 完整恢复前预览数据、明确确认，并先生成本地恢复前备份；恢复失败回滚。
- 不把演示记录导入正式库，不在日志输出密码或完整个人数据。
- 关闭系统自动云备份，用户显式导出或配置 WebDAV 后才传出数据。

### WebDAV 首版

界面明确使用「备份与恢复」，不称为已经实现双向同步。

- 配置服务地址、目录、用户名和密码或专用密码；支持测试连接、立即备份、自动备份、列表与恢复。
- 使用 HTTPS 并校验证书；凭据由 Android Keystore 保护，不进入源码、日志或备份。
- 自动备份默认关闭。启用后合并调度数据变化，联网执行，后台重试补偿；无变化时不重复自动备份。
- 每次上传独立的完整 JSON 快照，不覆盖上一份，不直接上传正在使用的数据库。
- 上传成功且回读校验通过后才显示成功；未完成或损坏文件不可恢复。
- 首版不自动删除远端历史；展示备份时间、大小、可用状态、上次成功时间和失败原因。
- 完整恢复替换本地业务数据，沿用预览、确认、恢复前备份与事务回滚。
- 不备份凭据、系统权限和设备提醒任务；换机后重新配置。恢复后不触发已经过期的休息提醒。
- 网络、认证或远端空间错误不影响本地训练，后台备份不承诺实时执行。
- 在用户实际服务上验证兼容性；后续同步另行设计合并、删除传播、并发和网页跨域。

## 五、实施、验收与交付

### 实施顺序

1. **准备基线**：检查项目、Flutter 和安卓工具链，固定版本；取得网站源码与备份样例。当前目录仍为空。
2. **设计系统**：建立三套品牌、六套外观、字体与间距变量、组件状态展示及导航；结合用户参考图细化视觉。
3. **训练闭环**：实现真实数据的开始训练、逐组编辑与保存、完成训练、历史查看及异常恢复。
4. **完整业务**：接入动作库、模板、周计划、特殊重量口径、计时提醒、统计和身体数据。
5. **迁移与备份**：完成旧数据导入、JSON 恢复、CSV 导出及 WebDAV。
6. **验证交付**：完成视觉检查、无障碍、系统能力和数据安全测试，生成签名 APK 与文档。

模拟数据可用于设计系统和组件预览；正式交付必须接入真实数据。未实现入口不得伪装成功，也不得将未执行测试标记通过。

### 验收

**功能与数据**

- 飞行模式完成核心流程；异常退出后恢复草稿、已完成组及训练状态。
- 复制、重复点击、历史修改、跳过和提前结束正确影响统计。
- 模板变化不影响历史；单双侧哑铃、辅助重量、有氧和缺失身体数据计算正确。
- 旧导入保真且去重；完整备份恢复无遗漏；损坏文件、未知新版本及迁移失败不破坏原数据。
- WebDAV 验证认证失败、网络中断、重试、回读失败和换机恢复。
- 后台与锁屏计时、取消、延长和权限拒绝不导致崩溃或重复提醒。
- 同签名覆盖安装及数据库升级保留数据。

**UI 与主题**

- 所有页面和导航可用，真实组数据可编辑、完成并持久化。
- 验证三品牌 × 浅深色的六套外观，以及三品牌下跟随系统的变化。
- 验证主题重启保留、切换期间输入不丢失、弹窗与图表同步换色。
- 验证小屏、横屏、平板、200% 字体、键盘弹出、返回操作和减少动画设置。
- 检查对比度、语义标签、触控尺寸和非颜色反馈。
- 输出六套外观的首页、正在训练及外观设置截图，并对其余页面完成深浅主题视觉巡检。

**测试执行**

运行静态检查、业务单元测试、数据库及备份集成测试、关键组件与主题测试，以及完整训练流程界面测试。安卓覆盖 8、9、13 及实施时最新稳定版；实际未执行或未实机验证的项目单独列出。
